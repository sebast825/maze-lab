## Benchmark Datasets

The project contains two benchmark sources:

### `manual/`

Hand-crafted mazes used for validation, debugging, and metric design.

These benchmarks are intentionally curated to represent specific maze patterns such as:

- Linear paths
- High ambiguity decisions
- Intricated routes
- Redundant loops
- Dead-end heavy layouts

The manual dataset is part of the repository and should be versioned.

---

### `generated/`

Automatically generated benchmark datasets used for large-scale statistical analysis.

These datasets are generated locally and are **not versioned** because they can be recreated at any time.

Examples:

- 50 DFS mazes (20x20)
- 50 Prim mazes (20x20)
- 50 Kruskal mazes (20x20)
- etc.

The `generated/` directory is ignored by Git.

---

## Dataset Selection

All benchmark scripts use the dataset configured in:

```ts
dataset.config.ts;
```

```ts
DATASET_MODE = "generated" | "manual";
```

- `generated` → operates on procedurally generated benchmark datasets.
- `manual` → operates on manually curated benchmark datasets.

This setting determines which benchmark files are analyzed, updated, or regenerated by the scripts below.

## Benchmark Scripts

### Generate Dataset

Creates benchmark mazes for all configured algorithms and sizes and stores them in `generated/`.

```bash
npm run generate-dataset
```

Typical use case:

- Generate large datasets
- Compare generation algorithms
- Build statistical samples

---

### Recalculate Metrics

Recomputes all maze metrics using the current implementation and overwrites the stored metrics.

```bash
npm run recalculate-metrics
```

Typical use case:

- A metric formula changes
- A new metric is introduced
- Difficulty calculations are updated

This avoids manually recalculating every benchmark.

---

### Generate Stats

Computes descriptive statistics for each metric:

- min
- p5
- p25
- p50
- avg
- p75
- p95
- max

```bash
npm run generate-stats
```

These statistics are used by the normalization system and scoring pipeline.

---

### Extract Normalization Specs

Builds normalization ranges from the generated statistics.

```bash
npm run extract-normalization-specs
```

The resulting specs are used to normalize metrics according to maze size.

---

### Analyze Metric Correlations

Computes Pearson correlations between metrics across the benchmark dataset.

```bash
npm run analyzeMetricCorrelations
```

Typical use case:

- Detect redundant metrics
- Validate new metrics
- Reduce feature duplication
- Understand metric relationships

Example findings:

- Strong positive correlation may indicate duplicate information.
- Strong negative correlation may indicate inverse measurements.
- Weak correlation may indicate independent information.

---

### Analyze Score Distribution

Analyzes the final scoring system across the benchmark dataset.

```bash
npm run analyzeScoreDistribution
```

Typical use case:

- Validate score normalization
- Detect scoring bias between maze sizes
- Inspect score category contributions
- Define difficulty ranges using score percentiles

---

## Recommended Workflow

When introducing or modifying metrics:

```bash
npm run generate-dataset
npm run recalculate-metrics
npm run generate-stats
npm run extract-normalization-specs
npm run analyzeScoreDistribution
```

Optional validation step:

```bash
npm run analyzeMetricCorrelations
```

Recommended process:

1. Generate a fresh benchmark dataset.
2. Recalculate all metrics.
3. Generate statistical distributions.
4. Update normalization specifications.
5. Verify score distributions and difficulty ranges.
6. Optionally inspect correlations and remove redundant metrics.

---

## Benchmark Philosophy

The goal is not only to solve mazes, but to understand **why a maze feels easy or difficult to a human player**.

Metrics should therefore be:

- Explainable
- Interpretable
- Statistically validated
- As independent as possible from one another

Correlation analysis helps identify metrics that may be measuring the same underlying property, while score distribution analysis helps validate that the scoring system remains balanced across different maze sizes.
